# 📚 הקורסים שלי: מערכת מעקב אישית

אתר אישי למעקב אחרי הקורסים. עובד גם מקומית (פתיחת `index.html`) וגם כאתר עם סנכרון בין המחשב לטלפון.

## איך פותחים
1. לחיצה כפולה על `index.html`. הוא נפתח בדפדפן.
2. מומלץ לפתוח ב-**Chrome** או ב-**Edge**, ולשמור את הדף במועדפים (Ctrl+D).
3. כדי לפתוח בטלפון, ראה בהמשך "שימוש בטלפון".

> הנתונים נשמרים **בדפדפן שבו פתחת**. אם תפתח את הקובץ בדפדפן אחר, תראה מערכת ריקה. אפשר להעביר את הנתונים עם ייצוא וייבוא.

## גיבוי ושחזור (חשוב!)
הנתונים נמחקים אם מנקים את נתוני הגלישה בדפדפן. לכן:

- **ייצוא גיבוי:** הגדרות ← "ייצוא גיבוי". קובץ JSON יורד לתיקיית ההורדות.
- **שחזור:** הגדרות ← "ייבוא גיבוי", ואז בוחרים את הקובץ. אם התחרטת, Ctrl+Z מבטל.
- **שמירה אוטומטית לקובץ** (Chrome/Edge): הגדרות ← "בחר קובץ לשמירה אוטומטית". מומלץ לבחור קובץ בתוך OneDrive, וכך יש גם גיבוי בענן. מאותו רגע כל שינוי נשמר לקובץ.
  אחרי שסוגרים ופותחים את הדפדפן, יופיע כפתור "אשר גישה לקובץ". צריך ללחוץ עליו פעם אחת, זו דרישת אבטחה של הדפדפן.
- אם עברו יותר מ-7 ימים בלי גיבוי, תופיע בדשבורד תזכורת עדינה.
- **גיבויים ישנים תמיד נקלטים:** כל ייבוא עובר דרך שדרוג אוטומטי למבנה הנתונים הנוכחי.

### שדרוג מבנה הנתונים (גרסה 2)
גרסה 2 הוסיפה שנה ומועד לסמסטרים, סיום קורס וציון סופי. השדרוג רץ לבד בפתיחה הראשונה, ו**לפני השדרוג נשמר עותק של הנתונים כפי שהיו**.
לשחזור המצב הקודם: הגדרות ← "הורד את הגיבוי שלפני השדרוג" ← "ייבוא גיבוי" ← בוחרים את הקובץ `course-tracker-before-upgrade-v2.json`.
מכשיר שעוד מריץ גרסה ישנה (למשל טלפון שלא רוענן) לא מוחק את השדות החדשים, רק לא מציג אותם. כדאי לרענן את האתר בכל מכשיר.

## סמסטרים קודמים
בתפריט **"סמסטרים"** יש את כל הסמסטרים לפי שנים (מהחדש לישן).
- **הוספה:** בוחרים מועד (חורף / אביב / קיץ) ושנה אקדמית לפי השנה העברית (תשפ״ז = 5787, תשפ״ד = 5784). אין הגבלה לאחור.
- **סמסטר פעיל:** "הפוך לפעיל". הדשבורד, "מה דחוף", הספירה לאחור, מערכת השעות, החזרה למבחן והטיימר מתייחסים רק אליו.
- **סמסטר ישן** נפתח בתצוגה מקוצרת: טבלת קורסים עם נקודות, סוג סיום וציון, שאפשר לערוך ישירות.
- **הזנה מהירה:** בתוך סמסטר ← "הזנה מהירה" ← מחפשים קורס בכל קטלוגי הפקולטה (שם או מספר, גם בן 6 ספרות) ← הוא נכנס לטבלה ← ממלאים ציון ← **"שמור"**.
  קורסים שנכנסים כך נשמרים בלי הרצאות ומשימות, ונספרים בממוצע ובנקודות כמו כל קורס.
- **קורס שלא בקטלוג** (הכרה, מעבר ממוסד אחר): "קורס שלא בקטלוג", ואז מקלידים שם, מספר (לא חובה), נקודות וציון או "עובר" / "פטור".

## תכנית הלימודים (קטלוג הפקולטה)
בתפריט **"תכנית לימודים"** יש את כל מקצועות המסלול שבחרת, מסודרים בלשוניות (מוצגות רק הלשוניות שיש להן נתונים בקטלוג):
- **חובה** — לפי השיבוץ המומלץ בסמסטרים, כולל דרישות "N נק׳ מתוך רשימה" (למשל קורסים מדעיים).
- **קבוצות התמחות / קבוצות בחירה** — עם מקצועות החובה או הליבה של כל קבוצה וכמה מקצועות צריך.
- **התמחות** (הנדסה אזרחית) — חלקי ההתמחות (חובה, פרויקט, בחירה עם ★) וההתקדמות בכל חלק.
- **בחירה פקולטית** (כולל רשימות כמו רשימה א׳/ב׳ עם מינימום נקודות), **מעבדות**, **בחירה חופשית** — הרשימות והכללים.

**פקולטות ומסלולים שיש כרגע** (מסלול ראשי בלבד בכל פקולטה):
| פקולטה | מסלול | שנים |
|---|---|---|
| הנדסת חשמל ומחשבים | 004004-1-000 | תשפ״ד, תשפ״ה, תשפ״ו, תשפ״ז |
| מדעי המחשב | 023023-1-000 כללי ארבע־שנתי | תשפ״ז |
| מדעי הנתונים וההחלטות | 009216-1-000 הנדסת נתונים ומידע | תשפ״ז |

| הנדסה ביו־רפואית | 033033-1-000 | תשפ״ז |

**פקולטה ושנת קטלוג:** בוחרים בהגדרות (או בראש דף תכנית הלימודים). שנת הקטלוג היא בדרך כלל השנה שבה התחלת את התואר.
אם השנה שבחרת חסרה, מוצג הקטלוג הקרוב ביותר עם אזהרה ברורה. בהגדרות אפשר גם לסמן **אילו קבוצות** בחרת ו**איזו התמחות** — הן מוצגות ראשונות וההתקדמות מחושבת לפיהן (בקבוצות ההתקדמות מחושבת לכל הקבוצות בכל מקרה).
בראש הדף מופיעה שורת המקור: שם הקטלוג, תאריך המסמך, קישור ל-PDF הרשמי ומתי הנתונים נשלפו.
נתונים שלא אומתו או אי-התאמות שנמצאו בקטלוג עצמו מוצגים בתיבה "⚠ נתונים לא מאומתים", ומקצוע עם נתון חסר מסומן ב-**?**.

לחיצה על **"הוסף"** יוצרת את הקורס (שם, מספר, נקודות ומבנה סטנדרטי) בסמסטר שנבחר למעלה.
קורס שכבר אצלך מסומן **"אצלי"** — ההתאמה לפי מספר הקורס, אז כדאי למלא מספר גם בקורסים שהוספת ידנית (גם המספר הישן בן 6 הספרות עובד).
בראש הדף רואים כמה נקודות חובה ובחירה פקולטית יש בקורסים שלך וכמה קבוצות הושלמו. **זה לא תחליף לבדיקה מול הקטלוג הרשמי והמזכירות.**

### איפה הנתונים
```
catalogs/<faculty>/<year>.json        קטלוג אחד לשנה (5784 = תשפ״ד). לא דורסים קטלוג ישן — מוסיפים קובץ חדש.
catalogs/<faculty>/<year>.fixes.md    כל תיקון ידני: מה היה במקור (טקסט ה-PDF), מה תוקן ולמה + אי-התאמות פתוחות
catalogs/bundle.js                    נוצר אוטומטית ע״י סקריפט הבדיקה — זה מה שהאתר טוען. לא עורכים ידנית.
tools/validate-catalogs.js            סקריפט הבדיקה
```
בכל קובץ יש `source` (קישור, תאריך העלאה / יצירת ה-PDF, תאריך שליפה), `knownIssues` (אי-התאמות שנבדקו ותועדו) ו-`verify` (דברים שעוד צריך לאמת).

### בדיקת הקטלוגים (חובה אחרי כל שינוי)
צריך Node.js (גרסה 18 ומעלה). מתוך תיקיית הפרויקט:
```
node tools/validate-catalogs.js           # בודק, ואם הכול תקין — כותב את catalogs/bundle.js
node tools/validate-catalogs.js --check   # בודק בלבד
```
הסקריפט בודק בכל קטלוג:
- סה״כ = חובה + בחירה פקולטית + בחירה כלל־טכניונית.
- סכום נקודות החובה בכל סמסטר = הסכום המודפס בקטלוג, וסכום כל טבלאות החובה = סך החובה המוצהר.
- אין קורס כפול (ברשימת הקורסים, בחובה, במעבדות, בכל קבוצה).
- מספרי קורסים תקינים (8 ספרות בתבנית הטכניון `0XXX0YYY`).
- אין נקודות זכות חסרות או לא סבירות (שלילי, מעל 10, לא בכפולות של 0.5).
- אין מקצוע חובה בסמסטר שלא קיים (1–8), וכל מקצוע שמוזכר (בקבוצה, כחובה בקבוצה, כחלופה) קיים ברשימה.
- יש מקור ותאריך.

**כשיש שגיאה הסקריפט לא מתקן כלום ולא כותב bundle** — הוא עוצר ומדפיס מה לא מסתדר. בודקים מול ה-PDF ומחליטים:
טעות בהקלדה שלנו → מתקנים את ה-JSON ומתעדים ב-`fixes.md`. אי-התאמה בקטלוג עצמו → מוסיפים ל-`knownIssues` עם הסבר (ואז היא מוצגת כאזהרה באתר ובפלט הבדיקה).

### עדכון שנתי
**בתחילת כל שנה אקדמית: להוריד קטלוגים חדשים ולהריץ את הבדיקה.**
1. **איפה:** באתר לימודי הסמכה — ugportal.technion.ac.il ← מידע לסטודנטים ← "קטלוג לימודים <שנה>" (למשל `קטלוג-לימודים-תשפז-2026-27`). בדף יש PDF לכל פקולטה.
   - מזהים את הקובץ לפי **מספר הפקולטה בתחילת השם**: `04` חשמל ומחשבים, `23` מדעי המחשב, `09` מדעי הנתונים וההחלטות, `01` הנדסה אזרחית וסביבתית, `33` הנדסה ביו־רפואית.
   - **שם הקובץ משתנה משנה לשנה** (למשל `04-הפקולטה-להנדסת-חשמל-ומחשבים-תשפ״ה.pdf` לעומת `23-מדעי-המחשב-תשפז.pdf`, עם או בלי גרשיים) — לא לנחש כתובת, לקחת את הקישור מהדף.
   - תאריך ההעלאה מופיע בנתיב (`wp-content/uploads/YYYY/MM/`). לבדוק גם אם יצאה גרסה מעודכנת לשנה קודמת.
   - ההורדה ידנית (בדפדפן). את קובצי ה-PDF לא מכניסים ל-git (`*.pdf` ב-`.gitignore`).
2. **קובץ אחד לכל פקולטה+שנה:** `catalogs/<faculty>/<year>.json` (מעתיקים את השנה הקודמת ומעדכנים לפי ה-PDF: חובה, קבוצות, נקודות, סכומים, `source` עם כתובת, תאריכים ועמודים). מסלול ראשי אחד בכל קובץ (`track`, `trackName`).
3. כל שינוי שאינו העתקה ישירה מה-PDF — שורה ב-`<year>.fixes.md`. נתון לא ברור (נקודות חסרות, מספר לא תקין) — **לא מנחשים**: `knownIssues` או `verify`, ושואלים.
4. `node tools/validate-catalogs.js` עד שאין שגיאות, ואז `node tests/catalog.test.js`, ואז commit (כולל `bundle.js`).

### הוספת פקולטה חדשה (בלי לשנות קוד)
רשימת הפקולטות בהגדרות נבנית **רק מהקבצים**: מוסיפים `catalogs/<id>/<year>.json` עם `facultyName`, מריצים את הבדיקה, והפקולטה מופיעה.
שדות שכדאי להכיר (כולם רשות חוץ מהבסיס):
- `facultyPrefixes` — תחיליות מספרי הקורסים של הפקולטה (למשל `["0234","0236"]`); בלי זה — `004` (חשמל).
- `choices` — "לבחור N נק׳ מתוך רשימה" בתוך החובה, ו־`choice: {id, credits}` בטבלת הסמסטר שבה זה משובץ.
- `groups` (+ `groupsTitle`, `minGroups`, ולכל קבוצה `must` / `core` + `minCore`).
- `facultyLists` — רשימות בחירה עם `minCredits` / `starred`.
- `specializations` (+ `minSpecializations`) — חלקים עם `all` / `minCount` / `minCredits` / `minStarred`.

## הוספת קורס חדש
1. בדשבורד לוחצים **"קורס חדש"** (או מקש `n`).
2. ממלאים שם, מספר קורס, צבע וסמסטר, ואפשר גם קישורים ותאריכי מבחנים.
3. משאירים את הסימון על "צור מבנה סטנדרטי" כדי לקבל 13 הרצאות, 13 תרגולים ו-5 ש"ב (את התבנית אפשר לשנות בהגדרות).
4. בתוך הקורס, **"פריטים בבת אחת"** יוצר למשל 6 שורות "ניסוי {n}" בלחיצה אחת.

## סיום קורס וציון סופי
בדף הקורס ← **"סיים קורס"**. בוחרים סוג סיום (עם ציון / עובר / פטור / נכשל / נטש), ציון סופי, תאריך והערה ("מועד ב׳").
- אם הזנת רכיבי ציון עם משקלים בלשונית "ציונים", החלון מציע את הציון המחושב. אפשר לדרוס אותו, כי הציון הרשמי הוא מה שקובע.
- קורס שהסתיים מקבל תג (למשל **"הושלם · 87"**), יוצא מ"מה דחוף" ומהספירה לאחור, ונשאר זמין בדשבורד ובדף הסמסטר.
- **"עריכת הסיום"** משנה ציון או סוג. **"ביטול הסיום"** מחזיר את הקורס להיות פעיל. אפשר גם Ctrl+Z.

## ממוצע וציונים
בתפריט **"ממוצע וציונים"**:
- **ממוצע מצטבר משוקלל:** Σ(ציון × נק״ז) / Σ נק״ז, רק על קורסים שנכנסים לממוצע.
- **לפי סמסטר:** ממוצע, נק״ז שנצברו, מספר קורסים ומה היה הממוצע המצטבר אחריו. יש גם גרף מגמה.
- **התקדמות לתואר:** נק״ז שנצברו מתוך הסך שבקטלוג שבחרת (לא מספר קבוע), גם לפי קטגוריה (חובה / בחירה פקולטית / חופשית, ומעבדות).
- **"מה אם":** מקלידים ציון משוער לקורסים שעוד לא הסתיימו ורואים את הממוצע הצפוי.
- **"איזה ממוצע צריך":** מקלידים יעד, ומקבלים את הממוצע הדרוש ב-(Y·(C+R) − S) / R. כאן S הוא סכום ציון×נק״ז עד עכשיו, C הנק״ז בממוצע, R הנק״ז שנשארו ו-Y היעד.
- **סינון:** לפי סמסטר, לפי קטגוריה, או הוצאת קורס מסוים מהחישוב (תיבת "כלול" בטבלה). הקטגוריה נקבעת לפי מספר הקורס בקטלוג, ואפשר לשנות אותה ידנית לכל קורס.

**כללי החישוב** (הגדרות ← "כללי חישוב הממוצע"; הם לא נוחשו מתקנון הטכניון, אלא ברירות מחדל שאפשר לשנות):

| כלל | ברירת מחדל |
|---|---|
| קורס חוזר (אותו מספר קורס) | הניסיון האחרון קובע. אפשר "הגבוה" או "כולם". הנק״ז נספרות פעם אחת |
| ציון נכשל | נכנס לממוצע, בלי נק״ז |
| ציון עובר | 55 |
| פטור | מקנה נק״ז ולא נכנס לממוצע. אפשר לשנות לכל קורס |
| "עובר" ללא ציון, נטישה | לא בממוצע. "עובר" מקנה נק״ז, נטישה לא |

**זו הערכה לצורכי מעקב אישי. הממוצע הרשמי הוא זה שמופיע במערכת האקדמית של הטכניון.**

### הדף "המודל שלי"
בתפריט **"המודל שלי"**: כל המטלות שהגיעו ממודל, במקום אחד.
- כפתור **"רענן עכשיו"** (כשמחובר קישור), **"עודכן לאחרונה"**, ומתי השרת בדק לאחרונה.
- **"מה השתנה"**: רשימה של מטלות חדשות, מועדים ושמות שהשתנו, ומטלות שנעלמו ממודל, עם הערך הקודם ומתי זה נקלט.
  כשיש שינויים שלא ראית, מופיעה גם התראה בדשבורד ("נוספו 2 מטלות חדשות"). "סמן שראיתי" / "ראיתי" מנקה אותה.
- **לשוניות לפי קטגוריה** (ראו "קטגוריות" למטה), עם מספר הפריטים הפתוחים בכל לשונית. **"הכל"** מסודר לפי דחיפות: **באיחור** (באדום), היום ומחר, השבוע הקרוב, בהמשך. תרגולים והרצאות לא נכללים ב"הכל" כברירת מחדל.
- סינון לפי קורס, יחד עם הלשונית (קורס + קטגוריה). ליד כל פריט יש תיבה לשינוי הקטגוריה.
- תג **חדש** על מה שהגיע בסנכרון ועוד לא סימנת "ראיתי" (גם בדף הקורס), ו**ממודל** בדף הקורס. V ליד מטלה = **"סימנתי שהגשתי"**. זה הסימון שלך: לוח השנה של מודל לא מוסר סטטוס הגשה.
- מטלה שנעלמה ממודל **לא נמחקת**. היא מסומנת "לא מופיע יותר במודל", ואתה מחליט מה לעשות בה.

### ייבוא ידני של קובץ ‎.ics‎ (עובד בלי שרת ובלי חשבון באתר)
1. במודל: **לוח שנה** ← בתחתית העמוד **ייצוא לוח שנה** ("Import or export calendars" ← "Export calendar").
   לא מוצא את הקישור בתפריט? פותחים ישירות `https://<כתובת המודל שלך>/calendar/export.php`.
2. אירועים: **כל האירועים** (או "אירועים הקשורים לקורסים"). טווח: **אירועים אחרונים ו-60 הימים הבאים**. לוחצים **ייצוא** ושומרים את הקובץ.
3. באתר: **הגדרות ← סנכרון מטלות ממודל ← ייבוא קובץ ‎.ics‎**.

### מה קורה בייבוא
| מצב | מה המערכת עושה |
|---|---|
| מטלה חדשה | מסווגת (ראו "קטגוריות") ונכנסת לטבלה המתאימה בדף הקורס (מטלות → "שיעורי בית", תרגילי הכנה, בחנים ומבחנים, מעבדות…; נוצרת אם חסרה), עם תאריך יעד, קישור למודל ותג **ממודל · שעה**. תרגולים, הרצאות ואירועים שלא סווגו מוצגים רק ב"המודל שלי" |
| זיהוי הקורס | לפי הבחירה ששמרת → מספר הקורס בשם הקורס במודל (CATEGORIES) או בכותרת → שם הקורס. אם אין התאמה ודאית — ברשימת **"לא משויך"** בהגדרות, שם בוחרים קורס והבחירה נשמרת |
| ייבוא חוזר | המזהה (UID) של האירוע הוא המפתח, כך שאין כפילויות |
| השם או המועד השתנו במודל | הפריט מתעדכן ומסומן **"עודכן ממודל"**; לחיצה מראה את הערך הקודם. שם או תאריך ששינית בעצמך לא נדרסים |
| אירוע נעלם מהקובץ | לא נמחק. מסומן **"לא מופיע יותר במודל"** ואתה מחליט: להשאיר כפריט רגיל או למחוק. מסומנים רק מועדים מהיום והלאה, עד התאריך האחרון שבקובץ, כי מטלות ישנות פשוט יוצאות מטווח הייצוא |
| V, הערות, תגיות, כוכב | לא נדרסים לעולם; פריט שסימנת V נשאר מסומן |
| פריט ממודל שמחקת | לא נוצר שוב בייבוא הבא |
| פריט "ש״ב 3" שיצרת מראש | המערכת **מציעה** למזג (לא אוטומטית); במיזוג נשמרים הסטטוס, ההערות והשם שלך |
| אירועי "נפתח" (opens) | מדולגים — אלה לא מועדי הגשה |
| הגשה ב-00:00 | נרשמת כיום הקודם בשעה 24:00, כדי שספירת הימים תהיה נכונה |

### קטגוריות
ברירת המחדל: **מטלות והגשות · תרגילי הכנה · תרגולים · הרצאות · בחנים ומבחנים · מעבדות · אחר**, ועוד **"לא מסווג"**.
אפשר לשנות שם, מילות מפתח, להוסיף ולמחוק ב**הגדרות ← סנכרון מטלות ממודל ← קטגוריות וכללי סיווג** (או "ניהול קטגוריות" בדף "המודל שלי").
לכל קטגוריה: האם להוסיף פריטים לדף הקורס ולאיזו טבלה, האם להציג ב"הכל", או להסתיר לגמרי. כברירת מחדל תרגולים והרצאות לא נכנסים לדף הקורס.

איך אירוע מסווג (`CT.moodle.classify` ב-`js/moodle.js`):
1. **בחירה שלך** קודם לכול. היא נשמרת לפי הקורס במודל + שם האירוע עד " - " בלי מספרים, כך ש"מטלת מודל 1 - X" ו"מטלת מודל 2 - Y" באותו קורס מקבלים אותה קטגוריה. הסנכרון לעולם לא דורס אותה; משנים אותה בכל רגע מהתיבה שליד הפריט, או "שכח" ברשימת הבחירות.
2. **מילות מפתח** בשם, בעברית או באנגלית. עברית נתפסת גם אחרי אות שימוש (ו/ה/ב/ל/ש/מ/כ); אנגלית רק כמילה שלמה (HW2 כן, Syllabus לא). מילה שנמצאת בתוך התאמה ארוכה יותר של קטגוריה אחרת לא נספרת.
3. התאמה לשתי קטגוריות שונות, או לאף אחת: **לא מנחשים**. האירוע עובר ל**"לא מסווג"** ואתה בוחר.
4. בלי אף מילת מפתח, אבל מודל עצמו כתב "יש להגיש את '…'" / "תאריך הגשה …": מטלות והגשות.

פריטים שסונכרנו לפני הקטגוריות עוברים לטבלה הנכונה בסנכרון הבא, רק אם הם עדיין בטבלה שבה הם נוצרו. פריט שהזזת בעצמך נשאר במקום.
תרגול או הרצאה שנוצרו בעבר כפריט בדף הקורס עוברים ל"המודל שלי" רק אם לא נגעת בהם: בלי V, הערה, תגית, כוכב, ובלי שינוי שם או תאריך. "לא מסווג" לא מוציא פריט מדף הקורס.
אירועי תרגול/הרצאה לא מייצרים התראות "חדש/השתנה". כאלה שעברו מופיעים תחת "הצג גם מה שהוגש או עבר", ונמחקים מהרשימה 120 יום אחרי שיצאו מטווח הייצוא (אלה לא נתונים שלך).

כל ייבוא אפשר לבטל עם Ctrl+Z. הנתונים של הייבוא (שיוכים, רשימת "לא משויך") נשמרים עם שאר הנתונים ונכללים בגיבוי — אין בהם שום סוד.

### סנכרון אוטומטי דרך קישור (צריך חשבון באתר)
הדפדפן לא יכול למשוך את הלוח ממודל ישירות (CORS), ולכן פונקציה קטנה ב-Supabase (Edge Function בשם `moodle-ical`) מושכת אותו בשבילך.

**איפה הקישור נשמר:** רק ב-**Supabase Vault**, מוצפן במנוחה. הטבלה `moodle_feeds` מחזיקה רק את מזהה הסוד ב-Vault, את שם השרת ואת תאריך השמירה.
שמירה, קריאה ומחיקה רק דרך פונקציות SQL שבודקות `auth.uid()` (`moodle_feed_set` / `moodle_feed_get` / `moodle_feed_delete`). לאף משתמש אין גישה ישירה ל-Vault, ואין שימוש במפתח service_role.
את הקישור המפוענח קוראת רק פונקציית ה-Edge, עם האסימון שלך. האתר עצמו לא קורא אותו אף פעם.
לא ב-localStorage, לא בגיבוי ה-JSON (הגיבוי גם מסתיר כל `authtoken=` ליתר ביטחון), לא בקוד ולא ב-git. אחרי השמירה האתר מציג רק את שם השרת.

**הגדרה (פעם אחת):**
1. **Supabase ← SQL Editor ← New query** ← מדביקים את כל התוכן של `supabase/moodle.sql` ← **Run**.
   נוצרות הטבלה `moodle_feeds` (עם RLS, בלי הקישור עצמו), פונקציות השמירה / הקריאה / המחיקה מול Vault, טבלת מגבלת קצב שאין אליה גישה ישירה, והפונקציה `moodle_claim_fetch()`.
   - **מי שכבר הריץ את הגרסה הקודמת:** מריצים שוב את כל הקובץ. הקישור השמור עובר אוטומטית ל-Vault והעמודה הגלויה נמחקת. אחר כך חייבים לפרוס שוב את הפונקציה (סעיף 2).
   - Vault מופעל כברירת מחדל בפרויקטים של Supabase. אם יש שגיאה על `vault`: **Database ← Extensions ← supabase_vault ← Enable**, ואז להריץ שוב.
   - בדיקה: `select * from public.moodle_feeds;` אמור להראות שרת, תאריך וטווח בלבד, בלי קישור.
   - הקובץ גם מפעיל את `pg_cron` ואת `pg_net` ויוצר את המשימה `moodle-ical-refresh`. אם יש שגיאה עליהם: **Database ← Extensions** ← מפעילים `pg_cron` ו-`pg_net` ← מריצים שוב.
     בדיקה: `select jobname, schedule from cron.job;`. אחרי הריצה הראשונה (עד שעתיים): `select events, checked_at, error from public.moodle_snapshots;`.
2. **Edge Functions ← Deploy a new function ← Via Editor**. שם: `moodle-ical`. מדביקים את כל התוכן של
   `supabase/functions/moodle-ical/index.ts` ← **Deploy**.
   אחר כך, בהגדרות הפונקציה, מכבים את **Verify JWT** (ה-"Enforce JWT verification"): הפונקציה בודקת בעצמה את ההתחברות מול Supabase Auth, וזה עובד גם עם מפתחות ה-publishable החדשים.
   - לחלופין, מהמחשב: `npx supabase login`, ואז `npx supabase functions deploy moodle-ical --project-ref xugwweikrcievcqfmfgc --no-verify-jwt` מתיקיית הפרויקט.
     ה-login שומר אסימון אישי במחשב שלך בלבד. לא להכניס אותו לקוד.
   - **אין צורך באף מפתח או משתנה סביבה נוסף.** `SUPABASE_URL` ו-`SUPABASE_ANON_KEY` מוגדרים אוטומטית. לא משתמשים במפתח service_role.
3. באתר: מתחברים ← **הגדרות ← סנכרון מטלות ממודל** ← מדביקים את הקישור ← **שמור קישור** ← **בדוק קישור**.

**איך מפיקים את הקישור:**
1. מתחברים למודל כרגיל, ופותחים `https://moodle<מספר>.technion.ac.il/calendar/export.php` (למשל `https://moodle26.technion.ac.il/calendar/export.php`).
   זה הדף "ייצוא לוח שנה", שלפעמים לא מופיע בתפריט.
2. **ייצוא — אירועים:** בוחרים **כל האירועים** (All events). כך מגיעים גם אירועים כלליים ואישיים.
3. **עבור / טווח זמן:** בוחרים **טווח מותאם** (Custom range).
4. לוחצים **קבל כתובת לוח שנה** (Get calendar URL). **לא** את "ייצוא", שמוריד קובץ.
5. מתחת לכפתור מופיע קישור ארוך שמתחיל ב-`https://moodle…/calendar/export_execute.php?userid=…&authtoken=…`. מעתיקים אותו **במלואו**,
   מדביקים באתר (הגדרות ← סנכרון מטלות ממודל), ולוחצים **שמור קישור** ← **בדוק קישור**.

**הטווח של הקישור (נבדק מול קוד המקור של Moodle 4.5):**
- בקישור אין שום תאריך. רק `preset_what` (מה) ו-`preset_time` (איזה טווח). **מודל מחשב את הטווח מחדש בכל משיכה**, כך שזה תמיד חלון נע, והקישור לא "פג" בגלל הטווח.
- **טווח מותאם** (`custom`): מ-X ימים אחורה עד Y ימים קדימה, לפי הגדרות המנהל של המודל. ברירת המחדל היא 5 אחורה ו-365 קדימה. לא ידוע לי מה הטכניון הגדיר.
  האתר מציג את "האירוע הרחוק ביותר שהגיע", כך שרואים בפועל עד כמה רחוק הלוח מגיע.
- **אירועים אחרונים ו-60 הימים הבאים** (`recentupcoming`): 5 ימים אחורה עד 60 ימים קדימה, קבוע בקוד. גם זה חלון נע.
- **השבוע / החודש הזה או הבא**: מכסים רק שבוע או חודש. האתר מזהיר עליהם וממליץ להפיק קישור עם טווח מותאם.
- האתר שומר בצד מה הקישור מבקש (רק `preset_what` ו-`preset_time`, לא הקישור), ומציג את זה בהגדרות ובדף "המודל שלי".
- מתי בכל זאת צריך קישור חדש: אם מודל מתחיל לדחות אותו. אז מופיעה אזהרה קבועה בדשבורד.
- מודל משמיט מהייצוא פעילויות שלא גלויות לך (`uservisible`). מטלה שהמרצה עוד לא פתח פשוט לא קיימת בייצוא, ותגיע ברענון הראשון אחרי שתיפתח.
הקישור הוא מפתח סודי, כמו סיסמה ללוח השנה שלך (מועדים ושמות מטלות; לא קורסים, ציונים או הגשות).

**ניתוק וביטול (חשוב — בכנות):**
- **"נתק"** בהגדרות מוחק את הקישור מהחשבון שלך כאן, כולל הסוד ב-Vault.
- **בצד של מודל אי אפשר לבטל את הקישור בעצמך.** במודל, המפתח שבקישור מחושב מהמשתמש שלך (מזהה + נתון הסיסמה במודל + מלח של האתר).
  "קבל כתובת לוח שנה" מחזיר שוב את **אותו** קישור, ולא מפיק חדש. בכניסה דרך SSO של הטכניון גם החלפת סיסמה כנראה לא משנה אותו.
- אם הקישור דלף: פונים לתמיכת המודל של הטכניון ומבקשים לאפס את מפתח ייצוא לוח השנה של המשתמש (פעולה של מנהל מערכת).

**מה הפונקציה עושה ומה היא לא עושה:**
- מקבלת רק משתמש מחובר: בודקת את ה-JWT מול Supabase Auth, וקוראת את הקישור עם האסימון של המשתמש עצמו (כלומר דרך ה-RLS).
- מושכת רק מ-`https://moodle<מספר>.technion.ac.il/calendar/export_execute.php`. לא מאפשרת שרת אחר או פורט אחר, ולא עוקבת אחרי הפניות. כך היא לא יכולה לשמש proxy פתוח או לאפשר SSRF.
  אותו כלל נבדק שלוש פעמים: באתר, ב-SQL וב-פונקציה.
- מגבלות: משיכה אחת לכל משתמש כל 5 דקות, המתנה של עד 10 שניות, וקובץ של עד 2MB.
- לא רושמת את הקישור בלוגים ולא מחזירה אותו בתשובה.
- הודעות שגיאה בעברית: קישור לא תקין, קישור שמודל דוחה ("העתק אותו שוב ממודל"), מודל לא זמין, זמן המתנה שנגמר, קובץ גדול מדי.

**מתי מסתנכרן:**
- **בשרת, כל שעתיים, גם כשהאתר סגור.** משימת `pg_cron` ב-Supabase (בדקה 17 של כל שעה זוגית) קוראת לפונקציה `moodle-ical`, שמושכת כל קישור שמור ושומרת את הלוח בטבלה `moodle_snapshots`.
  בטבלה הזו יש רק את תוכן הלוח, וכל משתמש יכול לקרוא רק את השורה שלו.
- **באתר:** בכל כניסה, וכל 30 דקות כשהאתר פתוח, האתר קורא את הלוח האחרון מהשרת (בלי לפנות למודל). אם הוא השתנה, האתר ממזג אותו, מראה הודעה קופצת ומעדכן את "מה השתנה".
- **"רענן עכשיו"** מושך מיד ממודל (עד פעם ב-5 דקות).
- **אם הרענון בשרת לא רץ 3 שעות** (למשל עוד לא הותקן), האתר חוזר לשיטה הקודמת: הוא מושך ממודל בעצמו בכניסה (אם עברו 30 דקות) וכל שעה.
- את שני הרענונים של האתר אפשר לכבות בהגדרות. הרענון בשרת ממשיך לרוץ כל עוד יש קישור שמור. "נתק" עוצר אותו.

**איך הרענון בשרת שומר על הקישור:**
- המשימה המתוזמנת לא מכילה סוד בטקסט שלה. בכל ריצה היא קוראת מ-Vault סוד אקראי (`moodle_cron_secret`, נוצר אוטומטית ב-`moodle.sql`) ושולחת אותו לפונקציה בכותרת.
- הפונקציה מעבירה את הסוד לפונקציות SQL (`moodle_cron_feeds`, `moodle_cron_save`) שבודקות אותו מול Vault. בלי הסוד הנכון לא מקבלים כלום.
- כמו קודם: רק כתובות של מודל הטכניון, בלי מעקב אחרי הפניות, 10 שניות לכל קישור ועד 2MB. בלוגים נרשמים רק מספרים, לא קישורים ולא מזהי משתמש. אין מפתח service_role.
קישור שפג תוקפו מציג אזהרה קבועה בדשבורד עד שמתקנים. בלי אינטרנט האתר ממשיך עם מה שסונכרן לאחרונה.

**מגבלות הדיוק (בכנות):**
- זה רענון תקופתי, לא התראה מיידית. שינוי במודל נקלט בשרת תוך עד שעתיים, ומופיע באתר בכניסה הבאה או תוך 30 דקות אם האתר פתוח. "רענן עכשיו" מביא אותו מיד.
- ההתראה היא בתוך האתר בלבד. אין מייל או push.
- הייצוא של מודל מכיל רק את הטווח של הקישור (ראו למעלה). מטלה רחוקה יותר תופיע כשתיכנס לטווח.
- המודל עצמו עשוי לעדכן את הלוח באיחור, ואירועים שמרצה הסתיר או שאינם בלוח (למשל הגשה שמוגדרת רק בטקסט) לא יגיעו.
- זיהוי הקורס תלוי בשם הקורס במודל. מה שלא זוהה מחכה ב"לא משויך".

**למה לא "טוקן של אפליקציית מודל" (נבדק ב-2026-11-26, מול קוד המקור של Moodle 4.5):**
- **זרימת ה-SSO (`admin/tool/mobile/launch.php`):** מחזירה את הטוקן רק בהפניה לכתובת של האפליקציה (`moodlemobile://token=…`), לא לדף https רגיל. בדפדפן במחשב, בלי האפליקציה, אפשר להוציא אותו רק מכלי המפתחים. זו לא זרימה נקייה.
- **כניסה ב-QR:** עובדת רק מהאפליקציה הרשמית (הקוד בודק את זה ומחזיר `apprequired`).
- **דף "מפתחות אבטחה":** מציג טוקנים רק למי שיש לו הרשאה ליצור טוקנים, ובדרך כלל לסטודנטים אין.
- **הטוקן עצמו:** נותן את כל מה שהאפליקציה יכולה לעשות, כולל הגשת מטלות ושליחת הודעות. זה הרבה יותר ממה שצריך.
- **מסקנה:** נשארים עם iCal. סטטוס "הוגש" אמיתי אפשר לקבל רק בטוקן (`mod_assign_get_submission_status`), ולכן הוא לא נתמך.

**אם בעתיד ישתמשו גם סטודנטים אחרים:** הטבלאות, ה-RLS ומגבלת הקצב כבר עובדים לכל משתמש בנפרד. צריך רק להפעיל הרשמה ב-Supabase (היום היא כבויה בכוונה), לשקול אימות מייל ו-CAPTCHA בהרשמה, ולהוסיף את כתובות האתר שלהם ל-`ORIGINS` בפונקציה. לא לפתוח הרשמה בלי החלטה מפורשת.

## עוזר AI
העוזר משתמש ב-Claude של Anthropic. **הדפדפן אף פעם לא פונה ל-Anthropic ישירות:** כל בקשה עוברת דרך Edge Function בשם `ai` ב-Supabase,
שבודקת שאתה מחובר, סופרת את השימוש ושומרת על התקרות. מפתח ה-API נשמר **רק** כסוד ב-Supabase: לא בקוד, לא ב-git, לא בדפדפן ולא בגיבוי.

בהגדרות יש כרטיס **"🤖 עוזר AI"**: מצב החיבור, כמה נוצל היום, בחירת מודל ובדיקת חיבור. קריאת גיליון ציונים תגיע בשלב הבא.

### הצ'אט
פותחים בכפתור העגול **🤖** בפינת המסך, או במקש `a`. שואלים בעברית, למשל: "מה יש לי השבוע?", "אילו מטלות באיחור?", "מה הממוצע שלי?", "מתי המבחן במעגלים?".
- **איך זה עובד:** השאלה נשלחת לפונקציה בשרת, שמוסיפה הוראות קבועות ורשימה קבועה של כלי קריאה (`get_overview`, `list_courses`, `get_course`, `list_items`, `get_gpa`, `get_schedule`, `search`).
  כשהמודל מבקש כלי, **הכלי רץ בדפדפן שלך** (`js/agent-tools.js`) על הנתונים שבאתר, ורק התוצאה נשלחת חזרה למודל. מעל התשובה מופיעים תגים "🔎 קרא…" שמראים מה העוזר קרא.
- **רק קריאה:** בגרסה הזו לעוזר אין שום כלי שמשנה, מוחק או מייצא נתונים, ואין לו גישה להגדרות, לקישור של מודל, לחשבונות או למפתחות. אם מבקשים ממנו לשנות משהו, הוא מסביר איך לעשות זאת ידנית.
- **לא ממציא:** הוא מונחה לענות על הנתונים שלך רק ממה שהכלים החזירו, ולהגיד כשאין מידע.
- **תוכן חיצוני הוא נתונים:** כותרות ממודל והערות עלולות להכיל טקסט שנראה כמו הוראה. המודל מונחה לא לבצע הוראות מתוך תוצאות הכלים, ובכל מקרה אין לו כלים שמשנים משהו.
- **השרת לא מקבל מהדפדפן** הוראות מערכת, כלים, קבצים, תמונות או מודל שלא ברשימה. ההיסטוריה שנשלחת נבנית מחדש בשרת עם שדות מותרים בלבד, ויש תקרת אורך להודעה (2000 תווים) ולשיחה.
- **היסטוריית השיחה** נשמרת רק במכשיר הזה (localStorage, המפתח `ct.ai.chat`): לא בענן, לא בסנכרון ולא בגיבוי. היא נמחקת ב"שיחה חדשה", בהתנתקות ובהתחברות.
  עם כל שאלה נשלחות רק 24 ההודעות האחרונות.
- **עלות:** מתחת לכל תשובה מופיעים המודל והעלות. עם Haiku תשובה עולה בדרך כלל פחות מעשירית סנט. כל סבב כלים נספר כבקשה, ושאלה אחת יכולה להשתמש בעד 7 בקשות.
- **אין עדיין הזרמה (streaming):** התשובה מופיעה בשלמותה אחרי כמה שניות.

### הגדרה (פעם אחת)
1. **מפתח API:** נכנסים ל-[console.anthropic.com](https://console.anthropic.com) ← **API Keys ← Create Key** ← מעתיקים (מוצג פעם אחת בלבד).
   **מומלץ מאוד:** ב-**Settings ← Limits** מגדירים תקרת הוצאה חודשית (למשל $5). זו שכבת הגנה שנייה מעבר לתקרה היומית באתר.
2. **הסוד ב-Supabase:** **Edge Functions ← Secrets ← Add new secret**. שם: `ANTHROPIC_API_KEY`, ערך: המפתח ← **Save**.
   לא להדביק את המפתח בשום מקום אחר: לא בקוד, לא ב-`js/config.js`, לא בצ'אט.
3. **טבלאות השימוש:** **SQL Editor ← New query** ← מדביקים את כל התוכן של `supabase/ai.sql` ← **Run**.
4. **הפונקציה:** לפונקציה יש שני קבצים (`supabase/functions/ai/index.ts` ו-`handler.ts`), ולכן הכי פשוט מהמחשב:
   `npx supabase login`, ואז מתיקיית הפרויקט: `npx supabase functions deploy ai --project-ref xugwweikrcievcqfmfgc --no-verify-jwt`.
   - לחלופין בעורך של Supabase: **Deploy a new function ← Via Editor**, שם `ai`, ובעורך יוצרים שני קבצים בשמות `index.ts` ו-`handler.ts` עם התוכן מהפרויקט ← **Deploy**, ואז מכבים **Verify JWT** בהגדרות הפונקציה (היא בודקת התחברות בעצמה).
   - `SUPABASE_URL`, `SUPABASE_ANON_KEY` ו-`SUPABASE_SERVICE_ROLE_KEY` מוגדרים אוטומטית על ידי Supabase. מפתח ה-service role משמש בשרת בלבד, רק להפעלת מוני השימוש, ואין צורך להעתיק אותו לשום מקום.
5. באתר: **הגדרות ← 🤖 עוזר AI ← בדוק חיבור**. אמור להופיע "✅ העוזר עובד" (הבדיקה עולה כחלק אלפי סנט).

### תקרות (לכל משתמש)
- עד **$0.50 ביום** (היום מתחלף בחצות שעון ישראל), עד **10 בקשות בדקה**, עד **10 גיליונות ציונים ביום**.

## סנכרון בין מחשב לטלפון
הסנכרון עובד דרך **Supabase** (מסד נתונים חינמי בענן), והאתר מתארח ב-**GitHub Pages**.

**איך זה עובד:** כל שינוי נשמר מיד בדפדפן ונשלח לענן תוך כשנייה וחצי. כל מכשיר בודק כל 20 שניות, וגם כשחוזרים ללשונית, אם יש שינויים ממכשיר אחר. בלי אינטרנט ממשיכים לעבוד כרגיל, והשינויים נשלחים כשהחיבור חוזר. אם שני מכשירים שינו נתונים באותו זמן, המערכת שואלת איזו גרסה להשאיר.

### הגדרה (פעם אחת)
1. פותחים חשבון ב-[supabase.com](https://supabase.com) ויוצרים פרויקט חדש (אזור: Frankfurt / Central EU).
2. **SQL Editor** ← New query ← מדביקים את כל התוכן של `supabase/schema.sql` ← **Run**.
3. **Project Settings ← API Keys**: מעתיקים את **Project URL** ואת המפתח **anon / publishable** לקובץ `js/config.js`.
   המפתח הזה מיועד להיות גלוי. ההגנה על הנתונים היא בהרשאות שב-`schema.sql`: כל משתמש רואה רק את השורה שלו.
4. **Authentication ← URL Configuration**: ב-Site URL שמים את כתובת האתר ב-GitHub Pages.
5. נכנסים לאתר ← הגדרות ← **"הרשמה (פעם ראשונה)"** ← מאשרים את המייל ← **"התחבר"**.
6. **חשוב:** אחרי שנרשמת, ב-**Authentication ← Sign In / Providers** מכבים את **Allow new users to sign up**, כדי שאף אחד אחר לא יוכל לפתוח חשבון באתר שלך.
7. בטלפון: פותחים את כתובת האתר, מתחברים, ובוחרים **"הוסף למסך הבית"** (בכרום: ⋮ ← "התקן אפליקציה"; באייפון: שיתוף ← "הוסף למסך הבית").

### לשים לב
- בתוכנית החינמית, פרויקט שלא נעשה בו שימוש **שבוע שלם** נכנס להשהיה. במקרה כזה נכנסים ל-supabase.com ולוחצים **Restore**. הנתונים לא נמחקים.
- במחשב, הקובץ המקומי (`index.html` מהתיקייה) והאתר ב-GitHub Pages הם שני "מכשירים" נפרדים. מתחברים בשניהם, או משתמשים רק באתר.
- אפשר תמיד לייצא גיבוי JSON מההגדרות, גם כשהסנכרון פעיל.
